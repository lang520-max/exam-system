# 考试系统题库独立审计任务（2024—2026 四川专升本）

> 项目：`lang520-max/exam-system`（Spring Boot 在线考试系统）
> 本任务只针对**考试系统实际运行数据库中的全部题库与全部题目**，不是 Stepwise 学习网站。
> 用户指出系统实际题库总量在 2,000 道以上。**必须以实际目标数据库的只读盘点为准，不能把仓库里 300 道种子题当成全部题库。**
> 本轮只审计、只输出报告，不修改题目、SQL、数据库、评分逻辑或业务代码。

## 1. 任务目标

独立审计当前考试系统**实际数据库中所有题库、所有科目、所有状态的全部题目**（用户预期总量 2,000+），并对其中属于四川专升本理工农医类的英语、高等数学、计算机基础题目，以官方考试要求及 2024—2026 年可核实的真题/考后回忆资料作为参照。其他科目也必须纳入库存盘点、正确性、完整性、重复度审计；若没有对应考纲/真题来源，应明确标为缺少参照，不得套用四川专升本标准。回答：

1. 当前数据库导入链路里到底有哪些题？JSON、MySQL SQL、H2 SQL、追加脚本和历史更新脚本是否一致？
2. 每道题是否符合对应科目的官方考纲？
3. 每道题与可核实真题的关系是什么：原题匹配、近似转录、真题改编、仅同考点、原创考试风格题、无关或无法验证？
4. 题目、选项、标准答案、解析是否正确、完整、无歧义？
5. 是否有重复题、换皮题、错误题、低价值题、题型/难度失真？
6. 现有固定模拟卷与随机组卷配置是否合理地反映真实考试，而不是仅仅凑够 150 分？

### 关键：必须盘点实际数据库中的 2,000+ 题目

仓库代码表明题目并不只来自种子 JSON：教师端支持题库/题目 CRUD，`ExamImportService` 支持从 JSON 导入试卷时创建新题（单次导入上限 500 道），因此运行数据库完全可能含有未提交到 GitHub 的人工录入、批量导入或其他题库数据。

必须执行以下步骤：

1. 找到当前考试系统**实际使用的目标数据库**（优先用户正在使用的那套实例；先确认 dev/test/prod，不能误把 H2 测试库当成实际库）。
2. 使用已有的只读数据库连接/只读账号盘点全部 `question_bank` 和 `question`：
   - 总题数；
   - 按 bank_id、题库名称、subject 分组的题数；
   - 按 status 分组的题数；
   - 每个题库的题型、难度、答案/解析缺失数；
   - 重复题及重复 ID/异常关联；
   - 题库记录数、无题题库数、无效 bank_id 题数。
3. 逐条读取全部题目内容进行审计，至少导出字段：`id, bank_id, type, difficulty, content, options, answer, score, analysis, category, status`。如需分批读取，按主键游标分页，必须覆盖全量且不得漏页。
4. 将实际 DB 的题目 ID 与三份 JSON、MySQL SQL、H2 SQL、增量脚本、更新脚本做差异对照，明确区分：
   - Git 跟踪的种子题；
   - 数据库中额外导入/手工新增的题；
   - 已删除、已停用、草稿或其他状态题；
   - 同题重复、跨题库重复、ID 冲突或题目内容漂移。
5. **不要打印、提交或写入报告任何数据库密码、token、连接串中的凭据或 `.env` 内容。** 不要把数据库导出提交到 GitHub；报告只保存统计、问题摘要和必要的题目 ID/短片段。
6. 只能使用只读查询（SELECT / SHOW / EXPLAIN）。不得执行 INSERT、UPDATE、DELETE、DDL、存储过程或任何会改变数据库状态的语句。不要擅自修改生产环境权限或网络配置。

## 4. 逐题审计字段

每一道题都必须保留其数据库/JSON 原始 ID，并单独记录：

- question_id
- bank_id / 科目
- 原题型、难度、分值
- 原始题干、选项、答案、解析
- 考纲匹配章节/知识点
- 真题关系：exact_match / near_match / adapted_variant / same_topic_only / original_exam_style / unrelated / unverifiable
- 真题年份、来源 ID、URL、来源等级
- 匹配置信度及具体证据（不能只凭“感觉像”）
- 独立答案审校：verified / probable / conflict / incorrect / unreviewed
- 题目质量：高 / 中 / 低 / 不建议保留
- 重复关系（完全重复、换数字、同能力重复、非重复）
- 问题标签、建议动作

注意：same_topic_only 只表示同考点，不得标为真题改编；真题来源可信度与答案正确性必须分开评估。

## 5. 必做审计项目

### A. 数据一致性审计
- 对比三份 JSON、MySQL 全量 SQL、增量 SQL、H2 SQL、V4 更新脚本、Flyway migration。
- 找出同一 question_id 在不同文件的题干/选项/答案/解析/难度/分值/category 是否一致。
- 先盘点实际数据库所有题目（用户预期 2,000+），再追踪 1001—1300 种子题、数据库额外题目、追加题目与全部 ID 边界。
- 核查 data-shengben-add.sql 是否存在注释过期、导入重复、遗漏或 SQL 与生成脚本不一致。
- 核查 1253 修正是否在所有数据源一致。
- 核查模拟卷 question_snapshot 引用的题目是否存在、题目分值合计是否等于 150、考试时长和题目分布是否合理。
- 检查题库初始化与重复导入是否会覆盖人工修订或破坏已存在考试快照。

### B. 逐题内容质量审计
- 数学题独立重算，检查推导、定义域、端点、符号、积分区域、矩阵运算等。
- 英语题检查语法、搭配、语境、唯一答案、阅读依据、翻译/写作评分要求。
- 计算机题检查术语、Office 版本差异、函数、算法、数据库、网络、进制换算等事实准确性。
- 每题检查题干完整、选项合理、答案唯一、解析能否证明答案。
- 发现问题必须引用 question_id 和原文片段，不允许只写概括。

### C. 考纲覆盖
- 按三科官方考试要求列出完整知识点树。
- 每个知识点统计题量、题型、难度、分值。
- 识别缺失、过少、过度集中及明显偏离考纲的内容。
- 计算机办公自动化需特别关注 Word/Excel/PowerPoint 实际应用；英语不能只统计语法单选；高数不能只做极限/导数。

### D. 真题对照
- 先将可读取的回忆题面整理为“真题参照表”，再与实际数据库中全部适用题目逐题比较；300 道 Git 种子题只能单列为子集。
- 对 2024、2025 题面逐项比对；2026 只能使用真实可见的有限线索。
- 无法取得题面的来源只作为线索，不能进入 exact_match / near_match。
- 题干表述、选项、解题结构相似才可判为匹配；仅知识点相同只能是 same_topic_only。
- 说明各科真题匹配数量和匹配率时，分母必须清晰：当前考试系统题库题量、已核实真题题量、或考纲知识点数，不可混淆。

### E. 重复与模拟卷质量
- 识别完全重复、仅改数字、改写同模板、能力重复。
- 审查模拟卷是否有合理题型、难度、考点覆盖和时间压力。
- 不得只因为题目总分 150 就宣称符合四川真实试卷结构。
- 考试系统的重点是**正式考试体验与判分可靠性**，不是学习网站的学习路径、Anki、学习计划或课程内容。
