## 0. 先说用户反馈的那条：成绩单里选择题看不到原题

**这是真缺陷，而且比报告的 Bug 13 更严重**（报告只说筛选失效，没说题目本身看不见）。

- 接口 `/api/exams/records/{id}/result` 的 `AnswerItem` 里**只有 `questionContent` + 一个答案字母**：
  没有选项、没有解析。于是学生看到的是
  「题目：冯·诺依曼体系结构计算机的核心设计思想是（　　）／我的作答 B／正确答案 A」——
  **B 和 A 分别写了什么，无从得知**，等于看不到原题。
- 修法：
  1. `ExamResultVO.AnswerItem` 增加 `options`、`analysis` 两个字段，`ExamService.getResult()`
     从题库带出来（与 `correctAnswer` 同级：都是交卷后才返回，接口仅限本人）。
  2. `student/scores.html` 把选择题渲染成**完整选项列表**：正确项标绿 ✓、
     学生选错的项标红 ✗（多选题按字母集合逐个标记），题干下面再跟一段「解析」。
  3. `css/style.css` 增加 `.rv-opts / .rv-opt / .q-analysis` 样式（沿用政务风配色变量）。
- 实测（线上，记录 6）：

  | | 修复前 | 修复后 |
  | --- | --- | --- |
  | 选项元素 | **0 个** | **64 个**（25 行） |
  | 解析 | **0 条** | **25 条** |
  | 一行选择题的实际渲染 | `单选题 5 分 / 冯·诺依曼…（　　）` + `我的作答 A` | `单选题 5 分 / 冯·诺依曼…（　　）` + `A 存储程序与程序控制 ✓` `B 并行处理` `C 指令流水线` `D 虚拟存储` + `解析 冯·诺依曼于 1945 年提出存储程序原理…` |

## 2. 统一确认弹窗：`UI.confirm`

原来四处破坏性/不可逆操作用的是浏览器原生 `confirm()`：

| 位置 | 动作 |
| --- | --- |
| `teacher/questions.html` | 删除题目 |
| `teacher/exams.html` | 发布考试 / 结束考试 |
| `student/exam.html` | 有未作答题目时交卷 |

原生 `confirm()` 有三个问题：样式与系统无关、**阻塞整个 JS 线程**、不在 DOM 里（探测与读屏都看不到）。
`api.js` 里已有「退出登录」用的 `.modal-sm` 弹窗，这次把它抽成通用能力：

```js
UI.confirm({ title, text, okText, cancelText, danger }).then(function (ok) { … })
```

点「取消」、点遮罩、按 Esc 都返回 `false`；四处调用点全部改用它（`danger: true` 用于破坏性动作）。
实测（线上）：删除/结束都弹出**应用内**弹窗，取消后**没有发出任何写请求**。

## 5. 这一轮踩到的坑（写探针/脚本时）

1. **挑记录要挑「真的有作答明细」的**：本地 dev 库里有的考试记录只有一行空壳，
   探针点开第一行读到 0 行题目，把「成绩单看不到题目」误判成仍然失败。
   改成优先点「已出分」那一行。
2. **「可选字段」不该要求 `required`**：我第一版断言「所有注册字段都要 required」，
   而真实姓名/邮箱本来就标注可选 —— 断言写错了，会逼着代码做错事。
3. **要读的东西会在读之前消失**：答题页现在是「先弹提示、900ms 后跳走」，
   探针必须**边跳边读**（轮询里同时收 toast 和 URL），等页面稳定再读就只剩空数组。
4. **带中文的脚本不能用 `Set-Content -Encoding ASCII`**（老坑，又踩一次）：
   中文被写成 `?`，`grep -c` 的统计随之失真（那次打印出来的「命中 = 707」就是废数）。
   写远端脚本一律 `[System.IO.File]::WriteAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))`。
5. **数据不自洽会伪装成功能缺陷**：「只看错题」被报成「筛选完全失效」，
   实际筛选逻辑是对的，是 `is_correct=1` 与 `score` 互相矛盾。
   遇到「筛选/统计/分页不对」时，**先把底层数据拉出来对一遍口径**。
