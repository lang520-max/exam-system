# 部署到云服务器（2 核 2 GiB 裸机）—— 实测手册

> 本文所有结论均为 **2026-09-16 在一台阿里云 ECS 上实测**得到，不是推断。
> 命令可直接复制。配套脚本在 `deploy/`，两条路径：**有 SSH 用 `deploy.ps1`**，
> **没有 SSH 用 `deploy/workbench/install.sh`**。

---

## 1. 交付形态

```
公网 ──▶ Nginx(宿主, :80) ─▶ Spring Boot(systemd, :8080) ──▶ MySQL(127.0.0.1:3306)
                                                          └─▶ Redis(127.0.0.1:6379)
                                                          ✗  RabbitMQ 不装（见 §4）
```

- **不用 Docker**：2 核机器上跑 Maven / Docker build 极易 OOM，jar 在本机打好再上传；
  服务器只跑运行物（jar + systemd + MySQL + Redis + Nginx）。
- MySQL / Redis 只监听 `127.0.0.1`，公网不可达（比"改端口"更彻底）。
- 换系统盘前是 Windows Server 2022，已换成 **Alibaba Cloud Linux 4.0.6 (OpenAnolis)**。

## 2. 实测环境与内存曲线

| 项 | 实测值 |
| --- | --- |
| 系统 / 内核 | Alibaba Cloud Linux 4.0.6 (OpenAnolis Edition) / 6.6.102-8.alnx4.x86_64 |
| CPU | 2 vCPU（ecs.e-c1m1.large） |
| **内存** | **标称 2 GiB，实际可用 1670 MiB**（Hypervisor 预留，别按 2048 做预算） |
| swap | 2 GiB（脚本创建；空转不用，交卷高峰兜底） |
| JDK | OpenJDK 17.0.19（`/usr/lib/jvm/jre-17-openjdk/bin/java`） |
| MySQL | **8.0.46**（Source distribution，走 `/etc/my.cnf`） |
| Redis | **7.2.14** |
| Nginx | 1.30.4 |
| SELinux | Disabled（所以不需要 `semanage port`） |
| firewalld | 未运行（安全组即边界） |
| 磁盘 | ESSD Entry 40 GiB |

**内存实测（应用 + 全部中间件稳定运行后，`smoke.py` 打印）**：

| 进程 | RSS |
| --- | --- |
| java (JVM, `-Xmx384m`) | 297–305 MiB |
| mysqld | 189–194 MiB |
| redis-server | 16 MiB |
| nginx | 14 MiB |
| **合计** | **≈ 530 MiB** |
| 系统可用 | **844–875 MiB** |

结论：**2 核 2 GiB 够用，余量约 850 MiB**。关键调参（都在 `deploy/server/bootstrap.sh` 里）：

- JVM：`-Xms128m -Xmx384m -XX:MaxMetaspaceSize=160m -XX:MaxDirectMemorySize=48m -XX:+UseSerialGC`
  （堆按**实际可用** 1670 MiB 定，不按标称 2 GiB 定）
- MySQL：`innodb_buffer_pool_size=96M`、**`performance_schema=OFF`**（省 150–200 MiB）、
  `max_connections=100`、`skip-log-bin`、`loose-mysqlx=OFF`
- Redis：`maxmemory 96mb`、关持久化（只放幂等键/登录计数/token 黑名单）
- systemd：`MemoryHigh=850M` `MemoryMax=1000M` —— 越界时让应用自己死掉重启，
  而不是让 OOM Killer 去杀 MySQL（MySQL 的 oom_score 通常更高，被杀会整站不可用）

## 3. 两种部署路径

### A. 有 SSH（推荐）：`deploy.ps1` 一条命令

```powershell
# 密钥（推荐）
.\deploy\deploy.ps1 -Server 47.109.157.25 -Port 2222 -User root -Key D:\keys\exam_ecs.pem
# 密码（密码放环境变量，不进命令行历史）
$env:EXAM_SSH_PASSWORD = '...'
.\deploy\deploy.ps1 -Server 47.109.157.25 -Port 2222 -User root
# 只更新代码（环境已就绪）
.\deploy\deploy.ps1 -Server 47.109.157.25 -Port 2222 -User root -Key ... -SkipBootstrap -SkipData
```

> **端口为什么是 2222**：本机所在的家宽（电信）**封了出站 22 端口**（详见 §5.1）。
> 服务器上 sshd 同时监听 22 与 2222（`/etc/ssh/sshd_config.d/99-exam-port.conf`），
> 安全组里 2222 只放行**你自己的出口 IP**。

### B. 没有 SSH：Workbench 里跑 `install.sh`

安全组不放行 22 时，用控制台的「远程连接 → Workbench」（走云助手通道，不依赖 22）。
把部署包传上去后：

```bash
cd /root && tar -xzf exam-deploy.tar.gz && bash exam-deploy/install.sh
```

`install.sh` 会做：环境侦察（**先打印仓库里 MySQL/Redis/Nginx 的可用版本**）→
`bash -n` 语法自检 → bootstrap → 起服务 → 灌演示数据 → 冒烟 + 内存 → 打印公网地址。

打包用 `deploy/tools/make-bundle.ps1`（**强制自检 10 个必需文件**，含包根目录
`install.sh` —— 手工组装漏过一次，服务端直接 `No such file or directory`）。

> 也可以直接在 Workbench 的网页终端里**被驱动**：它用 xterm.js 的 **DOM 渲染器**，
> 文字在 DOM 里可读、输入框可写（`Input.insertText` 整行插入；**逐键高速发送会丢字符**）。
> 本会话就是这么把部署做完的（见 §5.10）。

## 4. 为什么关掉 RabbitMQ

2 GiB 跑不动「MySQL + RabbitMQ + Redis + JVM + Nginx」全家桶（只 Erlang VM 就要 200–300 MiB）。
`APP_RABBITMQ_ENABLED=false` 时：不注册 `@RabbitListener`、交卷走同步判分，业务语义一致
（见 `docs/会话交接-项目当前状态.md` §3.4）。

**但这暴露了两个真 bug（都已修复，见 §6）**：

1. 判分降级判据用错 → 交卷后客观题不判分，要等 2 分钟补偿任务；
2. RabbitMQ 健康指示器仍在 → `/actuator/health` 变成 `DOWN`（HTTP 503），
   容器健康检查 / nginx `/health` / 监控全部误报「服务不可用」。

## 5. 踩坑清单（按踩到的顺序，都有实测证据）

### 5.1 家宽封出站 22 —— 最初所有「22 不通」都是这个原因

现象：安全组里 22 规则明明正确（`125.68.189.76/32`、允许、优先级 1），sshd 也在
`0.0.0.0:22` 监听，但从本机连始终 `timeout`。

**决定性对照测试**（凡"连不上某端口"都该先做这一步）：

```
github.com:22    => timeout      github.com:443   => open
gitee.com:22     => timeout      47.109.157.25:80 => open
gitlab.com:22    => timeout      ssh.github.com:443 => open
```

结论：**运营商封的是出站 22，跟服务器无关**。解法：sshd 加听 2222 + 安全组放行 2222。

### 5.2 Windows 实例没有 sshd：`refused` 与 `timeout` 的读法

换系统盘之前那台是 Windows：`Administrator` 用户名 + 22 无监听。
判读要点：**`refused` = 包到主机了、只是没人监听；`timeout` = 有东西在丢包**。
- 80 → `refused`：说明安全组放行、主机防火墙放行、只是没服务；
- 22 → `timeout`：Windows 防火墙对无监听端口**静默丢包**（不是 RST）。

阿里云 Linux 镜像默认用 `root`；Windows 镜像才用 `Administrator`，
而 Windows 默认没有 sshd（只有 RDP 3389）——**用户名本身就是系统类型的线索**。

### 5.3 systemd `ExecStart` 不展开「命令位置」上的变量 → 无限 `203/EXEC`

```
Main process exited, code=exited, status=203/EXEC     ← 每 5 秒一次，计数器涨到 17
（journal 里一行 Java 输出都没有 —— JVM 从未启动）
```

原因：unit 写的是 `ExecStart=$JAVA_BIN $JAVA_OPTS -jar app.jar`，
而 **systemd 不展开命令位置上的变量**（社区为此提过
[systemd#23235](https://github.com/systemd/systemd/issues/23235)），
首段不是有效路径 → `execve()` ENOENT。

解法：`ExecStart=/opt/exam-system/start.sh`（**字面路径**），
由这个包装脚本从 `/etc/exam-system/java.env` 读出 java 路径与 JVM 参数后 `exec`
（调 JVM 参数仍然只改 java.env 一处）。

### 5.4 装完包必须 `systemctl daemon-reload`，否则「找不到服务单元」

`dnf install mysql-server` 成功后立刻 `systemctl list-unit-files | grep mysqld` 可能是空的
→ 脚本误判成「MySQL 没装」。装包后先 `daemon-reload`，并用三重探测兜底
（`list-unit-files` / 直接读 `/usr/lib/systemd/system/*.service` / `systemctl cat`）。
真找不到就自建兜底单元（含 `mysqld --initialize-insecure` + 给空密码 root 补随机密码）。

### 5.5 `java.env` 权限：640 root:**exam** + 目录 750

`start.sh` 以 **exam 用户**运行，而 `java.env` 一开始是 `600 root:root`、目录 `700 root:root`
→ 读不到 → `JAVA_BIN` 为空 → systemd 侧又是 `203/EXEC`（表现和 §5.3 一模一样，极易误判）。

正确权限：

| 文件 | 权限 | 谁能读 |
| --- | --- | --- |
| `/etc/exam-system/` | `750 root:exam` | root + exam（exam 要能穿过目录） |
| `java.env` | `640 root:exam` | **只有 java 路径与 JVM 参数，无密钥** |
| `exam.env` | `600 root:root` | 仅 root（含 DB/Redis/JWT 密钥，由 systemd 读取后注入进程环境） |
| `start.sh` | `755 root:root` | 人人可执行、只有 root 可改 |
| `app.jar` | `640 exam:exam` | root + exam |

### 5.6 启动前自检：把「无限重启」翻译成「一句真报错」

`deploy-app.sh` 会先以 exam 用户**前台试跑**（最长 60 秒）抓真实 Java 输出，再交给 systemd。
**但自检的判据必须精确**：一开始用 `Exception` 当失败信号，
而 Spring Security 启动日志里那行过滤器链包含 **`ExceptionTranslationFilter`**
→ 循环立刻退出 → 把还有 1 秒就启动完成的应用杀掉，误报「自检失败」。
现在只认 `Started ExamApplication` / `APPLICATION FAILED TO START` / `Error starting ApplicationContext`。

### 5.7 MySQL 调参写入位置：`/etc/my.cnf` 未必 include `/etc/my.cnf.d`

ACL4 的 MySQL 是发行版自编译包。脚本先探测 `!includedir`，
有就写 `/etc/my.cnf.d/zz-exam-system.cnf`，没有就**追加**到 `/etc/my.cnf`
（绝不能覆盖写，那会毁掉包自带的 datadir/socket 配置）。
落地后立刻回读验证：`SELECT @@innodb_buffer_pool_size, @@performance_schema`。

### 5.8 RHEL 系 MySQL root 的初始密码与"改过之后重跑"

首次安装 root 是随机密码（在 `/var/log/mysqld.log`）、且处于 expired 状态，
必须 `--connect-expired-password`。脚本会把它改成随机强密码并记到
`/etc/exam-system/mysql-root.txt`（`MYSQL_ROOT_PASSWORD=...`），
**重跑时优先用这份留档**，否则会误判「连不上 root」。

### 5.9 云厂商标称内存 ≠ 可用内存

标称 2 GiB → `MemTotal` 只有 1670 MiB。JVM 堆按实际值配（384m 而非 512m）。

### 5.10 驱动 Workbench 网页终端的两个要点

- Workbench 用 **xterm.js DOM 渲染器**：`.xterm-rows` 的 innerText 就是终端屏幕，可读；
  输入框是 `.xterm-helper-textarea`。
- **输入必须整行原子插入**（CDP `Input.insertText` + 单独发 Enter）。
  逐键 `dispatchKeyEvent` 发 360 个字符会把 `/` 等字符丢掉、甚至把 shell 打成 `/` 乱码后 `logout`。

> 给脚本/命令「打字」比粘贴更稳的做法：把命令写进文件再逐行执行，
> 彻底绕开 PowerShell 的多层引号（本会话踩了三次）。

## 6. 这轮修掉的两个应用 bug

### 6.1 判分降级判据用错（严重）

```java
// 错：RabbitTemplate 只要 classpath 有 starter-amqp 就必然存在（Spring Boot 自动配置提供），
//     与 app.rabbitmq.enabled 无关 → 降级路径永不触发
if (rabbitTemplate != null) { ...投 MQ... } else { ...同步判分... }
```

实测现象：交卷 → `ERROR 判分消息投递失败，将由「待判分补偿任务」重判` →
客观题成绩要等 **2 分钟**（补偿任务判据是 `end_time` 早于 120 秒）。

修法（`ExamService`）：判据改成 `rabbitEnabled`（`@Value("${app.rabbitmq.enabled:false}")`）；
并且 `sendGradingTask` 投递失败时**就地同步判分**（补偿任务只作为最后兜底）。

**为什么 262 个测试没抓到**：test 档用 `spring.autoconfigure.exclude` 排除了
`RabbitAutoConfiguration` → 容器里根本没有 RabbitTemplate bean → 走的是同步路径。
**测试环境的 bean 拓扑与生产不一致，恰好把 bug 盖住了。**

回归测试 `GradingDegradationTest` 用 `@MockBean RabbitTemplate` 把生产拓扑补回来。
已实测「有牙」：把判据退回错误写法，该测试立刻失败（状态停在「待判分」）。

### 6.2 关掉 RabbitMQ 时健康检查误报 DOWN

`/actuator/health` 返回 `{"status":"DOWN"}`（HTTP 503），而应用一切正常 ——
Spring Boot 自带的 RabbitMQ 健康指示器每次都会去连不存在的 broker。

修法（`application.yml`）：让指示器跟着开关走

```yaml
management:
  health:
    rabbit:
      enabled: ${app.rabbitmq.enabled:false}
    redis:
      enabled: ${app.redis.enabled:false}
```

## 8. 运维速查

```bash
systemctl status exam-system          # 服务状态
journalctl -u exam-system -f          # 实时日志
journalctl -u exam-system -n 100 --no-pager
free -m                               # 内存余量（关注 available ≥ 400 MiB）
python3 /opt/exam-system/deploy/server/smoke.py     # 随时复测（含内存实况）
bash /opt/exam-system/deploy/server/deploy-app.sh --rollback   # 回滚上一版 jar
```

> ⚠ **冒烟测试会污染演示数据 —— 演示前别在有真实演示记录的库上跑它。**
> `smoke.py` 的流程是「开考 → 取题 → 交卷 → 查成绩单」，它挑的是**已存在的、
> 仍在考试中的记录**：2026-09-17 实测踩到，它对前一天 21:46 开考的记录在第二天
> 15:44 才交卷，于是演示记录变成「用时 1077 分钟、得分 18/100」，
> 还留下 3 条"超时"和 1 条"考试中"的空记录 —— 用户一眼就看出"和真实情况不一致"。
>
> **正确做法**（二选一）：
> 1. 演示前用 `smoke.py` 验证没问题，但**演示数据要在之后重建**（或干脆在演示前的
>    最后一轮部署后再跑一次数据修复）；
> 2. 更稳的做法：冒烟用**独立测试账号**，别碰演示账号的进行中记录。
>
> 修复脚本思路（本机 `.deploy-tools/repair-demo-data.sh`）：删掉 status=0/3 的空记录 →
> 按「每 9 题错 1 题」重建客观题作答与分数 → 让部分记录保持 `待判分`（答辩演示教师批改用）、
> 部分记录把主观题也判掉成为 `已出分` → **记录总分 = 各题得分之和**（不自造分数，
> 保证成绩单自洽）→ 交卷时间 = 开考时间 + 45~84 分钟且小于卷面时长。
> 注意试卷 100 分里主观题占 38 分，所以未批改的记录最多只显示 62 分，
> 想演示"及格"必须有已批改的记录。

> ⚠ **改完演示数据还得防着应用自己再改它 —— 补偿判分扫描会刷新交卷时间。**
> 实测第二轮：数据刚修好（用时 56 分钟），重启服务后 2 分钟内又变回 1089 分钟。
> 根因在 `GradingTxService.complete()`：收尾用 `compareAndSetSubmit()` 推进状态，
> 而那条 SQL 是 `SET status = ?, end_time = NOW(), ...` ——
> 补偿扫描每 2 分钟找一次「`status=1`（待判分）且 `end_time` 早于阈值」的记录重判，
> 顺手把**交卷时间刷成"现在"**，于是旧记录的用时越来越离谱。
>
> 演示机跑的是 `APP_RABBITMQ_ENABLED=false`（同步判分），这个扫描本来就没有用武之地
> （它的用途是兜住 MQ 丢消息/消费者进死信），所以直接调成一天一次：
> ```bash
> # /etc/exam-system/java.env 的 JAVA_OPTS 末尾追加（start.sh 会按空格拆开传参）
> -Dapp.exam.pending-grade-sweep-interval-ms=86400000
> systemctl restart exam-system
> ```
> 关掉之后再修数据才稳（实测 4 分钟后四项记录保持 56/67/78/71 分钟不变）。
> 这条也说明一件更一般的事：**演示数据不是"改一次就完"，要先弄清有没有定时任务在动它**。

| 文件 | 用途 |
| --- | --- |
| `/etc/exam-system/exam.env` | DB/Redis/JWT 等运行时环境（0600 root） |
| `/etc/exam-system/java.env` | java 路径与 JVM 参数（改完 `systemctl restart exam-system`） |
| `/etc/exam-system/mysql-root.txt` | MySQL root 随机密码（RHEL 系路径下生成） |
| `/opt/exam-system/start.sh` | 启动包装脚本（systemd 的 ExecStart 指向它） |
| `/opt/exam-system/install.log` | Workbench 安装路径的全量日志 |

## 9. 安全现状与建议

- **安全组**：只放行 80（0.0.0.0/0）与 2222（**仅你自己的出口 IP**）；
  MySQL/Redis 端口不开，服务本身只监听 127.0.0.1。
- **22 端口**：服务器仍监听（阿里云系统默认规则放行 0.0.0.0/0），但你家宽出站被封、
  实际用不上；**建议把安全组里那条系统规则的 22 也收紧或删掉**。
- **演示口令是 `123456`**：这是刻意的（答辩方便），但对外长期暴露有风险。
  收口二选一：① 改口令；② 安全组把 80 也限制到指定 IP（答辩现场用校园网/热点）。
- **HTTPS**：当前是纯 HTTP。上域名后用 certbot 签 Let's Encrypt 即可，配置改动很小
  （nginx 站点文件里加 443 server 块 + 跳转）。
- 密钥/口令都在服务器上随机生成（`openssl rand`），**不在仓库里**；`.env` 已被 `.gitignore` 排除。

## 11. 人脸识别的部署（V3 新增，2026-09-17）

功能本身的设计与排查见交接文档 §15，这里只讲**服务器侧要做什么**。

### 11.1 三步（顺序不能换）

```bash
# ① 验通云 API（RAM 角色临时凭证 + 真实调一次 CompareFace）
sudo bash /opt/exam-system/deploy/server/check-face-api.sh
#    看到 Confidence 才算通；报鉴权错就回去检查角色的 viapi-facebody:CompareFace 权限

# ② 给 8443 加 HTTPS（摄像头只在安全上下文可用）
sudo bash /opt/exam-system/deploy/server/setup-https.sh --self-signed
#    有域名时：--domain exam.xx.edu.cn（走 LE 的 DNS-01，不碰 80 端口，避开备案拦截）

# ③ 打开门禁（幂等，--off 可回滚）
sudo bash /opt/exam-system/deploy/server/enable-face.sh
```

### 11.2 为什么用 8443 而不是 443

大陆阿里云 ECS 上**未备案域名走 80/443 会被拦截**。换非标端口可以立刻跑通，
备案下来后把 `--port 443` 传给 `setup-https.sh` 即可（它生成的 nginx 站点是按参数写的）。
域名解析（A 记录 → 公网 IP）不需要备案，只有"在 80/443 上提供服务"才需要。

### 11.3 需要的控制台操作

| 项 | 位置 | 要点 |
| --- | --- | --- |
| 开通人脸比对 1:1 | 视觉智能开放平台 → 人脸人体 | 找到 `CompareFace`，确认有可用额度 |
| RAM 策略 | RAM → 权限策略 | **动作名是 `viapi-facebody:CompareFace`** —— 视觉智能开放平台的产品前缀是 `viapi-`（写成 `facebody:CompareFace` 在 RAM 里"没有这个动作"）。<br>**最省事**：直接给角色挂系统策略 **`AliyunVIAPIFullAccess`**，不用自己写 JSON |
| RAM 角色 | RAM → 角色 → 创建角色 → 信任主体**类型=云服务**、名称=**云服务器 ECS** | 角色名如 `exam-ecs-face`。选成「阿里云账号」的角色**不会出现在** ECS 的授予列表里 |
| 授予实例 | 实例 → 右上角「⋯」全部操作 → 实例设置 → 授予/收回RAM角色 | 操作类型选「授予」→ 选角色。**无需重启实例** |
| 验证授予 | 实例内执行 | `curl http://100.100.100.200/latest/meta-data/ram/security-credentials/` → 返回角色名=成功，404=没绑上 |
| 安全组 | 实例 → 安全组 → 添加入方向规则 | 自定义 TCP `8443/8443`，来源按需（手机用 4G 时要放开，别只写家里 IP） |

### 11.4 症状对照表（省得到处猜）

| 现象 | 原因 |
| --- | --- |
| `8443 => timeout`（telnet/curl 都连不上） | 安全组没放行 8443 |
| 页面能开，点采集报 `PERMISSION_DENIED` | 证书警告没点"继续"，或浏览器没给摄像头权限 |
| **HTTPS 站点上登录/提交报 403 `Invalid CORS request`（页面能开，只有 POST 挂）** | nginx 用了 `proxy_set_header Host $host` —— nginx 的 `$host` **会丢掉端口**，于是应用（`forward-headers-strategy=native`）认为自己是 `https://IP`，而浏览器发的 Origin 是 `https://IP:8443` → 端口不匹配 → Spring 判为跨域请求 → 白名单为空就 403。GET 不带 Origin，所以只有 POST 中招。修法：`Host $http_host`（含端口）+ `X-Forwarded-Host/Port`，并把入口来源写进 `CORS_ALLOWED_ORIGINS` |
| 采集页提示"人脸库未加载" | `/vendor/face-api/face-api.js` 没取到（看 nginx 日志与 jar 里的静态资源） |
| 核验返回 `UNAVAILABLE` | 厂商侧问题：角色没绑/权限不对/服务没开通/欠费/超时（看 `face_verify_log.detail`） |
| 门禁开了但学生开考就报"人脸核验服务不可用" | 十有八九是没跑 §11.1 的①就开了门禁 |
| 明明眨了却超时 `NO_BLINK` | 阈值：开 `/face-test.html` 看 `ear / 基线 / 阈值` 三个数（见交接文档 §15.6） |

### 11.5 内存影响

人脸功能**不增加服务器常驻内存**：本地不跑人脸模型（比对在厂商侧），
底片是小图存库，前端那 1.86MB 模型只在你点"采集"时才下载到浏览器。
实测部署后 JVM 常驻仍约 290 MiB、系统可用约 846 MiB（2 核 2 GiB 机器）。
