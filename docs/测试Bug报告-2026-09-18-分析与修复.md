## 2. 关于 Bug 1 与 Bug 2：同一个根因，但症状要更正

报告把 Bug 1 写成「登出请求永久 inflight → 占用连接 → 后续登录被阻塞」。这一条**不成立**：

1. **服务端从不挂起**：`curl` 直接打 `POST /api/auth/logout`（带 token / 不带 token / 重复调用三种）
   都是 `200`，耗时 **0.21 / 0.21 / 0.23 秒**。
2. **登出真的生效**：CDP 实测点「退出登录 → 确认」后，用登出前的 refresh token 调
   `/api/auth/refresh` 得到 **401**（已在 Redis 黑名单里）。服务端日志也有
   `AuthController.logout 成功`。
3. **「永远 inflight」是 devtools 的显示**：发起登出的那个页面紧接着 `location.href` 跳走了，
   这个请求属于**已经卸载的页面**，Network 面板里就停在 pending —— 与「服务器不响应」是两回事。
   （另做了 A/B：`.deploy-tools/logout-ab.js` 用服务端日志数送达次数，带不带
   `keepalive` 都是 **3/3 送达**。所以 `keepalive` 只是**防御性**写法，不是这条的解药。）

**而 Bug 2 是真的，它就是「登录页看起来坏了」的机制**：

```
输入错误口令 → 后端 401（正确）→ 前端把**所有** 401 都当成「登录态过期」→ goLogin()
            → location.href = '/login.html?redirect=' + encodeURIComponent('/login.html')
```

于是一次失败的口令输入会：**把登录页跳向它自己**、清空表单、并把刚要显示的错误提示
一起抹掉（实测 `errorText=""`、`usernameKept=""`）。而且 `redirect` 参数会**层层嵌套**
（每次失败都往自己身上再套一层），URL 越来越长、页面反复重载 —— 用户看到的就是
「点了登录没反应/页面闪一下」，与报告里 Bug 1 的描述一致。

**修法（三处，都在源头）**：

1. `request()` 支持 `redirectOn401:false`：登录/注册接口的 401 是**业务结果**，
   不清会话、不跳转，交给调用方提示。
2. `goLogin()`：**已经在登录页就不跳**（自指 redirect 与嵌套从此不可能发生）。
3. `login.html` 对 `redirect` 消毒：只接受站内路径，拒绝 `/login.html` 自身、
   拒绝 `//host` 与 `/\host`（顺带堵掉开放重定向）。

## 6. 踩坑记录（写脚本时踩到的，供后来者省时间）

1. **所有标签页共享 localStorage**：CDP 每个场景开新标签页**不等于**干净会话，
   上一个场景的登录态会让下一个场景「看起来已经登录」，造出「重定向没发生」
   「找不到用户菜单」这类**假失败**。必须在**同源页面**上 `localStorage.clear()` 再 reload
   （`about:blank` 是不透明源，清不了）。第一版就因此误判了 Bug 7/8/10。
   后来把「建立登录态」改成**直接调登录接口 + `Store.save`**（`verify-auth-scenarios.js`）：
   登录页在 localStorage 已有 token 时会立刻自动跳走，用它来铺登录态必然串味。
2. `Page.navigate` **只吃绝对 URL**，传 `/teacher/x.html` 会报 `Cannot navigate to invalid URL`。
3. `Page.addScriptToEvaluateOnNewDocument` 在 document-start 注入，那时
   `document.documentElement` 可能还是 `null`，`observe(null)` 直接抛错（要观察 `document`）。
4. 成绩页表格里**第一个 `.badge` 是「及格/不及格」**，状态徽标在第 6 列 —— 用
   `querySelector('.badge')` 取状态会取错（Bug 10 的断言因此假失败过一次）。
5. 验收「没反应」类缺陷时，**断言要读状态（元素/样式/URL/网络），不要读「有没有 toast」**：
   toast 2.6 秒就没了，探测时机稍晚就会误判成「完全没有提示」（Bug 3 的报告原文就是如此）。
6. **别用 `Page.loadEventFired()` 等导航**：chrome-remote-interface 里那个 promise 会被
   *后续任意一次* 导航事件兑现；前面若有 goto 超时留下悬挂 promise，后面的 goto 会「立刻返回」，
   读到的是上一页的 DOM（实测表现：线上 V9 读不到 `.nav-links`，而同一断言在单场景脚本里是过的）。
   改成轮询「URL 已是目标 + readyState 就绪」。
7. **跨公网别用固定睡眠**：本地 `sleep(1800)` 够用，线上经常不够，会造出
   「登录没成功」「元素为 null」这类假失败。等状态（token 出现 / readyState / URL），别等时间。
