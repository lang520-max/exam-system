## ① 题库关键词搜索

**问题**：题库管理只有「题库 / 题型 / 难度」三个下拉。300 道题里找一道特定题目只能翻页
（每页 10 条 = 30 页）。

**做法**：

- `GET /api/questions` 新增 `keyword` 参数，对**题干 / 选项 / 解析 / 答案**四处做模糊匹配。
  四处都匹配是刻意的：老师找题的入口常常是「学生问的那句话」，它可能只出现在某个选项或解析里。
- 实现用 `LOWER(x) LIKE {0}` 而不是 MyBatis-Plus 的 `like()`：**MySQL 的默认排序规则不区分大小写，
  而 H2 的 `LIKE` 区分** —— 直接用 `like()` 会出现「本地搜不到、线上搜得到」，
  属于最难查的一类不一致。统一转小写后两个引擎行为一致（有回归测试守着）。
- 前端：新增关键词输入框（`type=search`）、**回车即搜**、「重置」按钮，
  并把结果数写成「关键词「X」命中 N 道题」；空结果时提示里带上关键词本身。

**复验**：`共 300 道题` → 输入「极限」回车 → `关键词「极限」命中 19 道题`（请求确实带 `keyword=`）；
搜不存在的词 → 0 行 + 「没有匹配「zzz不存在的关键词zzz」的题目」；重置 → 回到 300 道。

## ② 学生自由练习模式

**问题**：只有正式考试（要人脸核验、要计时、要交卷判分），学生没法自由选题练习。

**做法**（按用户确认的「基础版」范围）：

| 层 | 内容 |
| --- | --- |
| 页面 | 新增 `static/student/practice.html`，学生侧栏加「自由练习」（第 3 项） |
| 接口 | `GET /api/practice/banks`（可练题库 + 题量）、`GET /api/practice/questions`（随机抽题）、`POST /api/practice/check`（对答案） |
| 流程 | 选题库/题型/难度/题量 → 逐题作答 → **提交后**立即看对错、正确答案、解析 → 下一题 → 本轮统计（已作答/答对/正确率） |

三条刻意的设计取舍：

1. **不写 `exam_record`**。练习要是落了库，「我的成绩」「及格率」「分数分布」立刻被污染
   （一次练习就是一条无意义的记录）。练习全程只读题库、只在内存里记本轮结果，
   练完即走 —— 有测试用「练习前后 `exam_record` 条数不变」把这条锁死。
2. **答案逐题给，不随题目下发**。抽题接口只返回题干与选项（复用 `QuestionVO`，天然不含答案与解析）；
   提交之后 `/check` 才把参考答案与解析给出来。否则一轮练习的答案可以被一次性拿走。
   测试直接断言响应体里不出现 `"answer"` / `"analysis"`。
3. **判分口径与正式考试完全相同**：客观题复用 `GradingEngine.normalize()` 再比较
   （`" a "` = `"A"`、多选 `"C,A"` = `"AC"`、判断 `"正确"` = `A`），不另写一套「练习版判分」——
   否则同一道题练习算对、考试算错，是最难解释的一类不一致。
   **填空/简答不假装判对错**：返回 `judged=false` + 参考答案与解析，由学生自评
   （正式考试里它们也是人评的，练习模式没有理由更"聪明"）。

**复验**：题库下拉 4 项（全部 + 3 个题库，带题量）、提示「当前共 300 道可练题目」；
抽 5 道 → 「第 1 / 5 题」判断题 2 个选项 → 选 A 提交 → 「**答对了** 你的作答 A / 正确答案 A / 解析…」
→ 下一题 → 结束本轮 → 统计卡显示正确率。

## ③ 自助修改密码

**问题**：登录页一直写着「忘记密码请联系教务」；密码泄露后学生/教师都无法自助更换。

**做法**：

- 后端 `PUT /api/auth/password`：`{oldPassword, newPassword}`。
  校验原密码（`passwordEncoder.matches`）、新密码 6-50 位（与注册同一套规则）、
  **新密码不得与原密码相同**；只更新 `password` 一个字段（白名单，不会覆盖 role/status）。
- **改完拉黑当前 refresh token**，前端清本地会话并回登录页 —— 强制重新登录。
  这是 `/api/auth/**` 里**唯一不 permitAll** 的接口（SecurityConfig 里逐条列出），
  必须先证明「你是本人」。
- 前端：顶栏用户菜单加「修改密码」→ 弹窗三个字段（原密码 / 新密码 / 确认新密码），
  字段级红框 + 常驻红字（与登录页、组卷页同一套 `.form-row.invalid + .field-error` 约定），
  原密码错时把服务端的「原密码不正确」显示在原密码字段下面。
- 登录页文案改为「忘记密码请联系教务；**已登录可在右上角用户菜单自助修改**」。

**复验**：菜单里有「修改密码」→ 弹窗 3 个密码框 → 空提交给 3 条字段级报错
（请输入原密码 / 请输入新密码 / 请再输入一次新密码）→ 原密码填错 → 弹窗不关、红字「原密码不正确」、
且**再登录一次仍用 123456 成功**（证明服务端确实没改）。
本地另跑了真改成功的路径：改完跳到 `/login.html`、本地 token 已清、旧密码 401、新密码 200。

## 已知限制（都是刻意的取舍）

| 项 | 说明 |
| --- | --- |
| 改密后旧 **access token** 仍能用到过期 | 无状态 JWT 的固有代价（默认 30 分钟）。本次拉黑了 refresh token，至少不能再用它换新 access token。要即时失效得引入 token 版本号或每请求查库 |
| 无 Redis 的实例上 refresh token 拉不黑 | dev/test 档的既有降级（`AuthService.logout` 注释里写明）。本地复验脚本对这一点做了环境判断，不误判成缺陷 |
| 练习不记录成绩 | 用户确认只要基础版：**没有**错题本、没有练习历史、不影响「我的成绩」。将来要做，建议单独建表而不是复用 `exam_record` |
| 练习抽题上限 50 道 | 防止有人一次把整个题库拉走；越界会夹紧而不是报错 |
| 关键词匹配 `%` / `_` 是通配符 | MyBatis-Plus 的 `like` 不转义，教师端搜索影响很小（搜「50%」照样能搜到） |

## 这一轮踩到的坑

1. **test 档的库不是空的**：`src/test/resources/data-test.sql` 有种子题目，
   关键词测试若不加 `bankId` 限定，计数会把种子算进来 —— 断言写成「等于 2」就直接假失败
   （实测得到 12）。**新写的测试一律限定到自己造的题库**。
2. **MockMvc 拼 URL 里的 `%20` 不会被当作 servlet 那样解码**：`?keyword=%20%20` 传进去后
   关键词不是两个空格，于是「纯空白等同于不传」那条断言假失败。
   改用 `.param(k, v)` 显式传参，绕开编码差异。
3. **`[System.IO.File]::ReadAllText('相对路径')` 又一次按进程 CWD 解析**（老坑，本轮又踩）：
   批量改写文件时先 `Set-Location` 是没用的。要么拼绝对路径，要么直接用编辑工具。
4. **`mvn -Dtest=A+B+C` 不认 `+`**：类名要用逗号分隔（`-Dtest=A,B,C`），
   否则报「No tests matching pattern」。
5. **改密码的自动化验证不能在线跑成功路径**：演示账号口令是 `123456`，
   被脚本改掉会让演示与其它复验脚本全部失效。脚本默认只验失败路径，
   真改的路径用 `ALLOW_PASSWORD_CHANGE=1` 在本地跑（本地重启即自愈）。
