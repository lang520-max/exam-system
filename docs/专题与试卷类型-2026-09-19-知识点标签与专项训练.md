## 1. 知识点体系（21 个）

分类不是凭空写的，是**逐题读题干**归出来的（三科各派一个子代理先做，再人工复核）：

| 题库 | 知识点（题数） |
| --- | --- |
| 高等数学 | 一元函数积分学 21 · 极限与连续 18 · 导数与微分 15 · 中值定理与导数应用 13 · 多元函数微积分 12 · 微分方程 8 · 级数与广义积分 8 · **向量代数与空间解析几何 5** |
| 英语 | 语法 71 · 阅读理解 10 · 词汇与短语 9 · 翻译 7 · 写作 3 |
| 计算机基础 | 计算机组成与工作原理 17 · 数制与编码 17 · 操作系统 15 · 计算机网络 15 · 办公软件基础 11 · 多媒体与信息安全 11 · 数据库基础 8 · 程序设计基础 6 |

**人工复核改了三处**（都记在 `scripts/fix-category-map.js` 里）：

1. **补了一个章节**：一开始给的七个允许值里没有「向量代数与空间解析几何」，
   子代理只好把 5 道向量题（点积 / 叉积 / 垂直判定 / 两点距离 / 直线方向向量）塞进「多元函数微积分」。
   四川专升本高数考纲里它是独立一章 —— 补上并迁移这 5 题。
2. **一道黎曼和题改判**：`lim Σ1/(n+k)` 按「含 lim 就归极限」的机械规则会被归到「极限与连续」，
   但它的解析明说关键是识别**定积分定义** → 迁到「一元函数积分学」（专项卷要用这条）。
3. **顺带修了一处废题**：计算机 `1253` 的 A 选项文字与题干**完全重复**（选择题的选项等于题干是废题），
   四个选项改成规范名称（局域网 / 城域网 / 广域网 / 个人区域网），解析里的 D 描述同步改。

> 归类是「人工复核过的标签」，所以单独放在 `scripts/data/category-<科>.json` 里，
> 与题目正文分开存 —— 改标签不会把整个题库文件的 diff 弄脏。
> 生成器用**白名单**校验每个标签（`CATEGORIES` 常量）：标签写错不会让任何东西报错，
> 只会让「按专题抽题」静默抽不到题，所以必须在生成阶段拦住。

## 2. 数据模型与四处 schema 同步

| 变更 | 位置 |
| --- | --- |
| `question.category VARCHAR(50) NULL` + 索引 | `db/migration/V4__category_and_paper_type.sql`（MySQL/Flyway）、`schema-h2.sql`、`src/test/resources/schema-test.sql`、`sql/init.sql` |
| `exam.paper_type VARCHAR(20) NOT NULL DEFAULT '模拟卷'` | 同上四处 |
| 已有 dev 库补列 | H2 `RunScript` 手工 ALTER（`CREATE TABLE IF NOT EXISTS` 对已存在的表是空操作） |

两条刻意的默认值：

- `category` **可空**：抽题的硬约束始终是题型与难度，知识点是「进一步收窄」的标签；
  老题/临时录的题不该因为没标签就用不了。
- `paper_type` **不可空、默认「模拟卷」**：老数据与不带该字段的导入 JSON 行为完全不变。

## 3. 四条入口

| 入口 | 行为 |
| --- | --- |
| 题库管理（教师） | 新增「知识点」筛选下拉（选项来自**库里实际用到的标签**并带题量）、列表新增知识点列、题目编辑器可填/改（datalist 提示已有标签）；关键词搜索现在也匹配知识点 |
| 智能组卷（教师） | 新增「试卷类型」下拉；**每条抽题规则**可指定知识点 —— 这就是「一元函数积分学专项训练」的做法 |
| 自由练习（学生） | 新增「知识点 / 专题」下拉（切题库自动换成该库的知识点）；每题显示专题徽标 |
| 导入试卷（教师） | 试卷可带 `paperType`，题目可带 `category`；引用已有题（`questionId`）时**忽略** category —— 题目在库里有自己的标签，导入一份卷子不该顺手改题库 |

两处列表（教师考试管理、学生我的考试）都显示「模拟卷 / 专项训练」徽标 ——
学生要能分辨「专项补短板」和「整卷掐时间」，用法完全不同。

### 关键取舍：**专题抽题不跨专题借题**

难度之间仍会互相借调（同一专题里简单题多、难题少是正常现象，算法照旧 5:3:2 分配 + 借调），
但**绝不跨专题借题**：借来的题不属于这个专题，「专项」就名不副实了。
所以专题题量不足时直接报错，并把话说清楚：

> 题库中「…」的「单选题」、专题「一元函数积分学」数量不足：需要 5 道，实际只有 3 道。
> 专题抽题不会跨专题借题（借来的题不属于这个专题），请减少题量或换一个专题

原先抽题用的三个 mapper 方法（`selectRandomIds` / `selectRandomIdsByType` / `countByTypeAndDifficulty`）
被两个「难度与知识点都可选」的方法取代（`countForPick` / `selectRandomForPick`）——
只留一条代码路径，避免「按难度抽」与「按专题抽」变成两套会各自漂移的实现。

## 4. 生成链路：三份 SQL + 一个稳定性检查

```
scripts/data/shengben-<科>.json        ← 题目正文（唯一可编辑来源）
scripts/data/category-<科>.json        ← 知识点标签（人工复核过）
        │  node scripts/gen-shengben-sql.js [--only-new]
        ├─→ sql/data-shengben.sql                 全量（MySQL，手工导入；开头带 DELETE）
        ├─→ sql/data-shengben-add.sql             增量（--only-new；只追加新题，不带 DELETE）
        ├─→ src/main/resources/data-h2-shengben.sql  H2 种子（MERGE KEY(id)，dev 自动加载）
        └─→ sql/data-shengben-v4-update.sql       **给已经在跑的库**补 V4（幂等）：知识点 + 1253 笔误 + 两张专项卷
```

`data-shengben-v4-update.sql` 是这一轮新增的第三条路：云端库里有真实作答，全量文件开头的 DELETE
会被外键挡住（而且是刻意设计），`--only-new` 又只导出「新题」，而这一轮变的恰恰是**已有题目**
（打知识点）与**旧题里的一处笔误**。知识点用一条 `UPDATE ... SET category = CASE id ... END` 写完（好读、好 diff）。

> **新增的硬约束检查**：`node scripts/check-paper-stability.js` 与 `git HEAD` 比，
> 要求 **12 张模拟卷的 `question_snapshot` 逐字节相同**，并列出题目正文的任何改动。
> 第一版这个脚本按列位置解析 SQL，V4 给 exam 加了列之后它一条都匹配不上 ——
> 于是「基线为空 ⇒ 没有差异 ⇒ 打印通过」。已改成不依赖列顺序，且**基线解析不出来就直接失败**：
> 「空基线的安全检查」比没有检查更危险。

## 5. 云端事故与修复（值得记住）

上线时踩到一个真事故，两个成因叠在一起：

1. **种子 id 与人工创建的卷子撞车**。演示库上有人（测试时）用「智能组卷」建了一张 6 题 70 分的卷子，
   它自然拿到了 `id=13` —— 而我把两张专项卷的 id 定成了 13/14。
   `ON DUPLICATE KEY UPDATE` 就把那张人工卷子的标题与题面**覆盖掉了**（该卷 0 条作答记录，已核对）。
2. **残留的时间窗把种子卷判死**。那张人工卷子被发布/结束过，带着 `start_time/end_time`；
   种子脚本没清这两个字段，于是「到点自动结束」任务在下一分钟就把新灌进去的专项卷判成「已结束」，
   学生端根本看不到它。

**修法（都已落进生成器）**：

- 专项卷 id 改到 **101/102**，并写明「种子数据不要占用人会自然用到的 id 区间」；
- 所有种子试卷的 `INSERT` **显式写 `start_time = NULL, end_time = NULL`**，
  `ON DUPLICATE KEY UPDATE` 里也一起清空 —— 否则该 id 上残留的任何时间窗都会让卷子被自动结束；
- 云端已删除 13/14 上插错的数据，按 101/102 重新录入，并**跨过一次「到点自动结束」扫描（70 秒）确认存活**。

> 教训：**种子数据不只是「插进去」**，它要能在一个有真实活动的库里反复执行 ——
> id 要避让、时间窗要显式清空、覆盖前要想清楚那一行是不是别人的数据。

## 7. 已知限制

| 项 | 说明 |
| --- | --- |
| 知识点靠人工/半自动打标 | 生成器只做**白名单校验**，管不了「这道题到底该归哪一章」。新增题目时要顺手填 category，否则它不参与按专题筛选 |
| 专项卷取题是**确定性**的 | 同题型内按 ID 升序取前 N 道（种子数据必须可复现，校验才能断言「卷内每题都属于该专题」）。现场要随机专项卷，用「智能组卷 + 知识点」 |
| 专项卷只取每类前 N 道 | 例如高数积分共 21 题，专项卷取 20 道（单选上限 10 道）。题量不足时得到一份更短的卷子，而不是报错 |
| 导入引用已有题时忽略 category | 有意为之：不该因为导入一份卷子而改掉题库里题目的标签 |
| 关键词搜索现在也匹配知识点 | 所以搜「极限」命中 21 道（含「极限与连续」整章 18 道 + 题干提到极限的 3 道）。这是刻意的：老师会直接搜专题名找一批题 |
