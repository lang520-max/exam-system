# 在线考试系统 项目思维导图

> 由脚本生成，与 docs/在线考试系统-思维导图.xmind 内容一致。

- 1. 项目定位
  - 从「社团管理式 CRUD」升级而来
  - 升级为：高并发 + 实时通信 + 异步处理
  - 升级前 → 升级后
    - JDK 1.8 → 17
    - Boot 2.7.18 → 3.2.5
    - MyBatis → MyBatis-Plus
    - Session 拦截器 → Spring Security + JWT
    - 无中间件 → Redis + RabbitMQ + WebSocket
    - app+mysql → 5 服务 Compose
- 2. 技术栈
  - JDK 17
  - Spring Boot 3.2.5
  - MyBatis-Plus 3.5.7
  - Spring Security 6.2 + jjwt 0.12.5
  - Redis 7（倒计时 / 幂等 / 缓存）
  - RabbitMQ 3（异步批量判分）
  - WebSocket（实时倒计时推送）
  - Spring AOP（操作日志 / 幂等切面）
  - MySQL 8 生产 / H2 测试
  - Docker Compose + Nginx
- 3. 数据库 6 张核心表
  - sys_user 用户
    - role 0管理员/1教师/2学生
    - UNIQUE(username)
    - BCrypt 存储密码
  - question_bank 题库
    - 组卷的抽题范围
  - question 题目
    - type 0单选/1多选/2判断/3填空/4简答
    - difficulty 1简单/2中等/3困难
    - options 存 JSON
    - 索引 idx_bank_type / idx_type_difficulty
  - exam 考试
    - question_snapshot 题目分值快照 ★
    - rule_config 组卷规则
    - status 0草稿/1进行中/2已结束
  - exam_record 考试记录
    - UNIQUE(exam_id,user_id) 防重复开考
    - status 0考试中/1待判分/2已出分/3超时
  - student_answer 答题明细
    - UNIQUE(record_id,question_id)
    - is_correct 2 = 待人工复核
- 4. 四大核心难点
  - ① 智能组卷算法
    - 按题型逐条处理规则
    - 难度权重 简单:中等:困难 = 5:3:2
    - ORDER BY RAND() LIMIT n 抽题
    - 用联合索引把候选集压小再随机排序
    - 库存不足向相邻难度借调，而非直接失败
    - 抽题结果落库为 question_snapshot
  - ② Redis + WebSocket 倒计时
    - Redis TTL 是剩余时间的唯一真相
    - 开考 SET exam:timeout:{examId}:{userId} EX 时长
    - ScheduledExecutorService 每秒推送
    - 断线重连从 Redis 读，不重置计时
    - 多端互踢：同 key 新连接关闭旧连接
    - TTL 归零推送 TIMEOUT 触发自动交卷
  - ③ 幂等防重复提交
    - 防线1：Redis Lua SETNX + EXPIRE 原子占位
    - 防线2：条件更新 UPDATE WHERE status=ONGOING
    - 防线3：UNIQUE(record_id,question_id)
    - Lua 保证占位与过期原子，避免幂等键永久残留
  - ④ RabbitMQ 异步判分
    - 交卷 → 抢占交卷权 → 落库 → 发消息
    - GradingConsumer 只管消息与 ack 语义
    - GradingEngine 是纯业务判分，可单测
    - 客观题自动判分
    - 主观题标记 is_correct=2 待人工复核
    - 手动 ack + 死信队列，失败重回队列
    - 无 MQ 时降级为同步判分
- 5. 判分规则
  - 单选：精确匹配，忽略大小写与空白
  - 判断：对/正确/T/√ 归一化为 A
  - 多选：全对才得分，少选多选错选均 0 分
  - 多选：排序去重，CBA 等价于 ABC
  - 主观题：不自动给分，待人工复核
  - 未作答：0 分且仍留明细
  - 分值口径：以试卷快照为准，不是题库默认分
- 6. 接口
  - 认证 /api/auth
    - login 返回 Access + Refresh 双 Token
    - register 强制学生角色
    - refresh 用 Refresh Token 换新 Access
    - me 当前用户（不返回密码）
  - 题库 /api/banks /api/questions
    - 增删改查 + 分页筛选
    - 删除题库前校验是否还有题目
  - 考试 /api/exams
    - POST 智能组卷（教师）
    - publish / end 状态流转
    - start 开考（幂等）
    - records/{id}/questions 取题（不含答案）
    - submit 交卷（需 X-Request-Id）
    - records/{id}/result 成绩单
    - {id}/stats 统计（教师）
  - WebSocket /ws/exam/{examId}/{userId}
    - COUNTDOWN 剩余秒数
    - TIMEOUT 时间到
  - HTTP 语义
    - 401 未登录 / 403 越权
    - 404 不存在 / 409 重复交卷 / 400 参数错
- 7. 前端页面（原生 HTML/CSS/JS，无需构建）
  - 共享基础层 js/api.js
    - fetch 封装 + 自动带 JWT
    - 自动解 code/message/data 信封
    - 401 自动跳登录页并带 redirect
    - Auth.requireRole 角色守卫
    - UI.esc 防 XSS / 时间格式化 / 幂等键生成
  - 登录注册
    - 注册只创建学生，注册后自动登录
  - 学生端
    - 我的考试：开始 / 继续 / 查成绩
    - 在线答题：答题卡 + 倒计时 + 到点自动交卷
    - 我的成绩：成绩单逐题明细 + 只看错题
  - 教师端
    - 考试管理：草稿到发布到结束 + 统计
    - 智能组卷：题型+数量+分值，实时预览总分
    - 题库管理：题库与题目增删改查 + 筛选分页
  - 倒计时两层保险
    - 优先用 WebSocket 服务端推送
    - 本地按 deadlineMillis 兜底计时
    - WebSocket 断了也不影响自动交卷

- 9. 部署

- 10. 踩坑记录

  - H2 小写化列别名，Map 取值恒为 null
  - 演示账号 BCrypt 哈希是错的
  - 业务异常返回 HTTP 200，监控失灵
  - 缺请求头被误报成 500
  - dev 档缺 Redis/RabbitMQ Bean 启动失败
  - 不带 profile 启动会去连不存在的 RabbitMQ
