### 必须知道的运行约束

1. **启动必须带 `dev` profile**（IDEA 的 run configuration 已设 `ACTIVE_PROFILES=dev`）。
   不带 `dev` 会走 `application.yml` 的 MySQL：**库不存在 + 密码错** → 500，
   并且因为注册了 `@RabbitListener`，没装 RabbitMQ 时会每 5 秒刷 `Connection refused` 堆栈。
2. **端口 8080** 常被 IDEA 里的应用占用。
3. 起临时实例做验证时用别的端口，例如：
   ```powershell
   $env:SPRING_PROFILES_ACTIVE='dev'; $env:SERVER_PORT='8099'
   mvn -B spring-boot:run        # 建议放后台任务
   ```

### 环境里两个"用不了"的东西（别浪费时间）

- **Hindsight 记忆工具全部 401**（`no apiToken is configured`）→ 既读不到也写不进。
- **modlens 视觉桥 429 余额不足**（`余额不足或无可用资源包`）→ **读不了图片**。

## 3. 已实现功能

### 3.1 核心流程
组卷（按题型+数量+分值，难度 5:3:2 权重随库存借调）→ 发布 → 开考 → 取题 →
交卷 → 判分 → 成绩 → 统计。

### 3.2 三处刻意设计的可靠性

| 能力 | 实现 |
| --- | --- |
| 防重复交卷 | 归属校验 + `status==ONGOING` 校验 + CAS 条件更新（三层） |
| 幂等 | Redis `SETNX`（有 Redis 时）+ 数据库条件更新兜底 |
| **交卷时限** | `ExamService.assertWithinDeadline()`，按 `start_time + duration` 判定，含 30 秒宽限；超时返回 409 |
| **超时清理** | `@Scheduled` 每 60 秒扫描，用 CAS 把过期 ONGOING 标记为 `TIMEOUT`，**只改状态不伪造 end_time/score** |

### 3.3 主观题判分：AI 自动 + 教师可复核

- **AI 评分**（`AiGradingService`）—— 走 OpenAI 兼容 `/chat/completions`，
  默认指向阿里云百炼（DashScope）兼容模式。**默认关闭**（按量付费）。
- **教师批改**（`ExamReviewService` + `teacher/exams.html` 的「批改」按钮）——
  教师可改**任何**一题，包括客观题与 AI 已打分的题。

### 3.4 中间件开关矩阵（`app.*.enabled`，全部默认关闭，prod 显式打开）

| 档位 | Redis | RabbitMQ | AI | 判分路径 |
| --- | --- | --- | --- | --- |
| 基类 `application.yml` | ❌ |  | ❌ | 同步 `GradingEngine` |
| `dev` | ❌ |  | ❌ | 同步；H2 文件库 |
| `test` | ❌ |  | ❌ | 同步；H2 内存库；定时任务关闭 |
| `prod` | ✅ | ✅ | 由 `AI_ENABLED` 决定 | MQ 异步 |

> 关掉 Redis 后：幂等退回数据库条件更新，倒计时降级为按 `deadlineMillis` 计算。
> 关掉 RabbitMQ 后：交卷时同步判分，业务语义一致。

### 3.6 前端改版的兼容性约定与验证方式

| 四川专升本 · 计算机基础题库 | 同上 | 模拟卷（一）（二）（三）（四）各 90min |

- 每卷 **25 题 / 总分 100 / 及格 60**；同科四卷**不重不漏**地覆盖全部 100 题；每科难度分布 40/44/16。
- **占用 ID**：题库 `1-3`、题目 `1001-1100 / 1101-1200 / 1201-1300`、试卷 `1-12`。
  其中 `1001-1050 / 1101-1150 / 1201-1250` 是首轮 150 题（2026-09-16 上午），
  每科后 50 题（`1051-1100` 等）是同日扩题补的。
- **12 张卷在种子里就是 status=1（已发布）** —— 若留成草稿，重置后的学生端会是空列表，
  看起来像功能坏了；「草稿 → 发布」流程仍可用「智能组卷」现场体验。
- 题目为**按考试大纲原创命题**，未逐字照抄真题；高数含 LaTeX（全部公式片段通过 KaTeX 编译）。

**加题的约定（重要，别破坏）**：新题一律【追加在 `addedIdFrom` 之后】，**绝不改动已有题的 ID**
（云端已有作答记录通过外键指向题目 ID）。因为卷子是按「题型 + ID 升序」取第 k 段来切的，
旧题 ID 更小、永远排在前面，所以**前两张卷的题面构成逐字节不变**，新题只进入后两张卷。

**数据与生成链路（改题目只改一处）**：

```
scripts/data/shengben-{gaoshu,english,computer}.json  ← 题目原始数据（唯一可编辑来源）
        │  node scripts/gen-shengben-sql.js           ← 生成 + 自检（默认用仓库内 KaTeX，免联网）
        │      └─ --only-new                          ← 只导出新增题目（追加到已在跑的库，不带 DELETE）
        ├─→ sql/data-shengben.sql                     （MySQL 全量，手工导入）
        ├─→ sql/data-shengben-add.sql                 （MySQL 增量，只含 addedIdFrom 之后的题与新卷）
        └─→ src/main/resources/data-h2-shengben.sql    （H2，dev 由 spring.sql.init 自动加载）
```

> 云端（已在跑的库）**必须用 `data-shengben-add.sql`**：全量文件开头的 DELETE 会撞上
> `student_answer` 的外键（旧题已被作答），这是刻意设计，避免静默删掉真实作答数据。

生成器会自检并在任何一项不过时报错退出：题量/题型/难度分布、答案必须落在选项内、
多选答案升序无重复、判断题选项、**解析非空**、四卷切分（每卷题数与总分）与「四卷并集
必须覆盖全部题目」、以及**用 KaTeX 编译每一个 `$...$` 片段 + 查「`$...$` 之外的
LaTeX 命令」**。**每卷的题目组成与每题分值由脚本按题型自动推导**（取每类题 ID 升序的第 k 段），
所以「卷子漏题、总分对不上」这类错误不可能靠人工疏忽溜过去。

> ️ **公式必须写在 `$...$` 里**。前端 `static/js/math.js` 的 KaTeX auto-render 只认
> `$$…$$` / `\[…\]` / `$…$` / `\(…\)`，写在定界符外面的 `\underline{...}` 之类
> **不会被渲染，学生会直接看到源码**。2026-09-16 实测踩到：高数 16 道填空题的答题空位
> 写成了裸 `\underline{\qquad\qquad}`，答题页上原样显示（第 19 题）。

> `collectBareTexProblems()` 专门查这一项；修好的写法是 `$\underline{\qquad\qquad}$`。

> ⚠️ `scripts/data/` 一度被 `.gitignore` 的 `data/` 规则**静默忽略**（该规则匹配任意层级
> 名为 `data` 的目录），题目数据差点进不了库。已加 `!scripts/data/` + `!scripts/data/**`
> 例外，并用 `git check-ignore` / `git status` 实测确认生效。**新增数据目录时要留意这个坑。**

> 已删除的旧产物：`scripts/gen-gaoshu-sql.js`、`sql/data-gaoshu.sql`、

1. **401 不等于「登录态过期」**。登录/注册接口对错误口令返回的也是 401；
   默认的 401 处理（清会话 + 跳登录页）会把登录页跳向它自己，把错误提示抹掉。
   这些接口一律传 `{ redirectOn401: false }`，由页面自己提示。
   `goLogin()` 另外做了「已经在登录页就不跳」的短路，自指 `redirect` 从源头不可能再出现。
2. **页面守卫抛的 `ApiError(401/403)` 是控制流，不是故障**。`requireLogin/requireRole`
   顶层抛出会让控制台留下 `Uncaught ApiError`（已用 `error`/`unhandledrejection` +
   `preventDefault()` 只吞这两个码）。新增会抛守卫异常的调用点时，别忘了这条约定。
3. **渲染函数要同时接受数字角色与字符串角色**（`renderNav(role)`：0/1 → teacher，2 → student）。
   页面传 `Store.getUser().role` 这种数字是很容易发生的，而按字符串比较会**静默走错分支**

### 3.13 第二轮缺陷修复（2026-09-18 下午，成绩单/确认弹窗/表单）

   不要再用浏览器原生 `confirm()`：它不在 DOM 里，自动化探测与读屏都看不到，

## 6. 安全设计与既定决策

延续以下**不可随意放松**的约定：

| 决策 | 理由 |
| --- | --- |
| 密码类配置**不给默认值**（`DB_PASSWORD` / `JWT_SECRET` / `AI_API_KEY`） | 缺失时启动失败，而不是静默用弱口令/公开密钥跑起来 |
| **AI 开启了却没给 key → 启动失败** | 静默降级会表现成「主观题永远 0 分」，比启动失败难查 |
| `LogAspect` **不记录参数值** | 曾经把登录明文密码打进日志 |
| 业务异常映射**真实 HTTP 状态码**（400/401/403/404/409/429） | 「HTTP 200 但业务失败」会让网关、监控、压测全部失灵 |
| 学生视角**剔除 `question_snapshot` 与 `rule_config`** | 否则开考前就能拿到卷面构成 |
| 非教师 `GET /api/exams` **强制 status≥1** | 草稿卷不该被学生看到 |
| `/vendor/**` **必须 permitAll** | 浏览器加载 `<link>/<script>` 不带 Authorization 头，否则 401 且页面不报错 |
| 默认**不允许任何跨域来源** | 原先是 `*` + `allowCredentials=true` |
| 登录限流：Redis 计数 5 次 / 锁 10 分钟 → 429 | Redis 异常时**放行**而非拒绝（登录是唯一入口） |
| `.env` 已在 `.gitignore`，密钥只放那里 | 已用 `git log --all -S` 全历史验证无泄露 |

## 7. 踩坑清单（按价值排序，都踩过并修好了）

### 7.1 MySQL 与 H2 对反斜杠处理不同 → 一份 SQL 不可能通用【实测】

| SQL 里写的 | H2 (MODE=MySQL) | MySQL 8.1 |
| --- | --- | --- |
| `'<\frac>'` | `<\frac>` | `<frac>`（反斜杠被当转义符吃掉） |
| `'<\\frac>'` | `<\\frac>`（多一个） | `<\frac>` |

所以 `sql/data-shengben.sql`(MySQL) 与 `data-h2-shengben.sql`(H2) **必须两份**。
两份由 `scripts/gen-shengben-sql.js` **从同一批 JSON 数据生成**，转义只在一处发生。
改内容要改生成脚本再重新生成（脚本会用 KaTeX 逐条校验公式）。

### 7.2 MyBatis-Plus 的 `logic-delete-field: status` 会吃掉草稿卷

配了它之后所有查询自动追加 `WHERE status = 1`：`insert` 成功但 `selectById` 返回 null。
**本项目刻意不配**（`status` 是业务状态，不是软删除标记）。

### 7.3 H2 会把列别名转小写

`SELECT COUNT(*) AS totalCount` 在 H2 里回来是 `TOTALCOUNT`，用 `Map` 接会拿到 null。
已改为强类型 DTO（`ExamRecordStats`）+ 下划线别名。

### 7.4 判分用了题库分值而不是卷面分值

会让一份全对的卷子只得 40/70。修法是判分与展示统一读 `exam.question_snapshot`。
`GradingScoreSnapshotTest` 是这条的回归测试。

### 7.5 `is_correct = 2` 被同时当作「部分正确」和「待复核」

列注释写的是「2-部分正确」，代码却拿它表示「待复核」；前端按 `isCorrect == 1` 判对错，
于是**主观题被显示成红色 0 分、答错**。
现在「待复核」用 `graded_by IS NULL` 表达（见 `GradedBy` / `Correctness`）。

### 7.6 `getResult()` 曾让学生永远打不开含主观题的卷子

它要求 `status >= GRADED`，而含主观题的答卷在复核前一直是「待判分」，
偏偏原先**没有任何复核接口**（`regrade()` 与 `reviewedBy/reviewedAt` 都是死代码）。
现在允许查看「待判分」成绩，返回「已知部分合计 + 待复核题数」，且此时 `passed` 为 null。

### 7.7 教师改分不能用 `compareAndSetSubmit`

它的条件是「待判分 → 已出分」。教师改一份 **AI 已出分** 的卷子时条件不成立，
于是**答案分数改了、记录总分却没变**（静默失效，最难查）。
改分走 `ExamRecordMapper.updateScoreAndStatus`（无条件更新），
测试 `canRegradeAlreadyGradedRecord` 守这个行为。

### 7.8 静态文件的生效方式

- Spring Boot 从 **`target/classes/static` 按请求读盘** → 改 `src/.../static` 后
  **同步到 `target/classes/static` 即生效，无需重启**：
  ```powershell
  Copy-Item src\main\resources\static\teacher\exams.html target\classes\static\teacher\exams.html -Force
  ```
- **Java 改动必须重启**应用。

### 7.9 PowerShell 的几个坑（我在本项目里踩了两次）

- **curl 传 JSON 会被吃掉双引号** → 必须写进文件用 `--data-binary "@file"`
  （用 `-d $json` 会得到 400，且容易被误读成业务错误）
- **读 UTF-8 文件**：`Get-Content -Encoding UTF8` 或 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`；
  默认编码读中文会变乱码，导致 `-match '中文'` 永远匹配不上
- **`!str.indexOf(x)` 是错的**（未找到时是 `!(-1)` = false）。我在脚本过滤和测试前提里各踩了一次
- **`[System.IO.File]::ReadAllText('相对路径')` 会按进程当前目录解析，不是 PowerShell 的 `Set-Location`**。
  用相对路径会抛 `DirectoryNotFoundException`，而 `$t` 变成 null 后
  后续的 `$t.Contains(...)` / `$t -match` 全部静默返回 false ——
  **安全检查会假装通过**。凡是要读文件内容，一律用 **Join-Path 拼绝对路径**。
- `ConvertFrom-Json` / `curl` 混用时注意引号层级

### 7.10 测试里的两个坑

- **`MockHttpServletResponse.getContentAsString()` 默认按 ISO-8859-1 解码**，
  响应未声明 charset 时中文变乱码，用中文做断言会莫名失败。
  新测试统一 `getContentAsString(StandardCharsets.UTF_8)`。
- **不要写"跟时钟赛跑"的测试**：超时清理定时任务必须在 test 档关掉
  （`app.exam.scheduling-enabled: false`），否则测试刚开考就被扫成超时，随机失败。

### 7.11 其它已验证的小结论

- **JWT 环境变量确实生效**：Spring Boot relaxed binding 把 `JWT_SECRET` 映射到 `jwt.secret`，
  优先级高于 yml。
- **`@Value` 的 `jwt.secret` 有硬编码兜底**（`JwtUtil`），prod 现在显式 `jwt.secret: ${JWT_SECRET}` 覆盖。
- **`/vendor/katex/katex.min.css` 的 `@font-face` 把 woff2 排第一** → 只保留 `.woff2` 不会 404。
- 我曾**错误推断**过两件事，实测推翻了：① 用户给的 API Key 形式不常见（带点、分段），
  我说"不像百炼格式" → 实际**可用**（直接打接口返回 HTTP 200）；② CORS 预检会被 Security 拦 → 实际返回 200。
  **先测再说。**

### 7.12 判分收尾曾经会改写「交卷时间」【2026-09-18 修复】

- **现象**：成绩单与统计里的「用时」越看越大。云端演示库实测两条记录
  `start_time` 是前一天、`end_time` 却是当天判分时刻 → 用时显示 **1123 / 1114 分钟**（真实 56 / 67）。
- **根因不在定时任务，而在判分收尾的 SQL**：`GradingTxService.complete()`（以及 `regrade()`）
  原先复用 `ExamRecordMapper.compareAndSetSubmit()`，而那条语句的语义是**学生按下交卷**，
  自带 `end_time = NOW()`。含主观题的卷子在 AI 关闭时会一直停在「待判分」，
  条件 `status = 待判分` 永远成立 → **每重判一次，交卷时间就往后推一次**。
  补偿任务 `sweepStuckPendingGradeRecords()` 恰好每轮都重判这类记录，于是它成了放大器。
- **修法**：新增 `compareAndSetGradingResult()`，唯一区别是
  `end_time = COALESCE(end_time, NOW())` —— 有交卷时间就保留，真为空才补。
  交卷路径（`ExamService.submitExam`）继续用 `compareAndSetSubmit`，语义不变。
- **回归测试**：`GradingCompensationTest` 的 `repeatedSweep_doesNotMoveSubmitTime`（连跑两轮补偿，
  交卷时间必须逐字不变）、`stuckPendingGrade_isRegraded`（补判到「已出分」同样保留）、
  `gradingResult_fillsMissingEndTime`（缺时间时兜底补上）。
  **已实测**：把调用退回 `compareAndSetSubmit` 这两条会失败（期望 3 分钟前、实得「现在」，
  且第二轮扫描返回 0 —— 因为交卷时间被推新后记录自己出了扫描窗口）。
- **教训**：**「改状态」和「记录学生动作」必须是两条 SQL**。一条 UPDATE 顺手写的
  `end_time = NOW()`，在被复用的那一刻就从「记录」变成了「污染」；
  幂等的重判路径最容易被这种副作用咬到（`status` 不变 ⇒ 条件更新照样生效）。

### 13.3 环境侧最坑的三条（换台机器也会遇到）

1. **systemd 不展开 `ExecStart` 命令位置上的变量** → 必须 `ExecStart=/opt/exam-system/start.sh`

2. **装完包要 `systemctl daemon-reload`**，否则 `list-unit-files` 看不到新单元，

3. **`java.env` 要让 exam 用户可读**（`640 root:exam` + 目录 `750`），

## 15. 人脸识别（V3，2026-09-17 新增）

需求原话：**注册需要人脸识别，考试也要人脸识别通过才允许考试**。

### 15.1 一句话架构

注册时采集底片 → 开考前现场抓拍 → **服务端**调阿里云
「视觉智能开放平台 - 人脸比对 1:1（`CompareFace`）」算相似度 → 结论落库 →
`ExamService.startExam()` 查库决定放不放行。活体（眨眼）在浏览器本地算，
身份比对在服务端，**两者缺一不可**。

### 15.2 三条刻意的设计取舍（改动前先读这段）

| 取舍 | 理由 |
| --- | --- |
| **服务不可用 ≠ 通过，也 ≠ 不通过** | 厂商超时/欠费/限流 → 记 `UNAVAILABLE` → 拦下 + 教师人工放行。当"通过"等于门禁失效；当"不通过"会冤枉学生 |
| **重试上限只算 `FAIL`/`LIVENESS_FAIL`** | 运维问题（欠费、网络）不该把学生锁死；`UNAVAILABLE` 不计入 3 次额度 |
| **门禁判据查库不查内存** | `face_verify_log` 里近期的 `PASS`/`OVERRIDE_PASS`（默认 5 分钟窗口）。服务重启、以后多实例部署都不失效，且天然留痕 |
| **先分「谁的锅」再决定拦不拦** | 厂商错误码以 `InvalidImage*` 开头（没人脸/分辨率不够/太模糊）→ 判 **FAIL**、扣一次重试额度、提示"重拍"，**这是学生自己能纠正的**；鉴权/限流/网络 → **UNAVAILABLE** 拦下 + 教师放行。真机联调发现的：先前一律按 UNAVAILABLE，学生会看到"服务不可用，请找监考老师"，而他其实只是没对准镜头 |

另外：**活体未过时服务端不调用厂商接口**（省一次调用费）；前端如实传 `liveness`，
但"能不能过"始终由服务端比对决定 —— 前端只影响体验，不影响结论。

### 15.3 库表与接口

- `user_face`（一人一条，UNIQUE user_id）：底片存 **JPEG 小图**（前端压到最长边 640、
  质量 0.7，约 20-40KB）。存图片而不是特征向量，是因为比对在厂商侧做，本地不跑人脸模型。
- `face_verify_log`：`scene`(ENROLL/EXAM_START/OVERRIDE) + `result`(PASS/FAIL/LIVENESS_FAIL/
  UNAVAILABLE/OVERRIDE_PASS) + `confidence` + `liveness` + `retry_no` + `ip_address` +
  `detail` + `operator_id`。教师端「人脸」面板就是读它，并从这里一键放行。
- `exam_record`：`face_verified` / `face_confidence` / `face_verified_at`（成绩单直接展示）。
- 接口：`POST /api/face/enroll`、`POST /api/face/verify`、`POST /api/face/override`（教师）、
  `GET /api/face/status`、`GET /api/face/logs`（教师）、`GET /api/face/config`（**公开**，
  登录页与考试列表要在没有 token 时知道门禁开没开）。

**加新表/字段时四处同步**：`db/migration/V3__*.sql`（MySQL）+ `schema-h2.sql` +
`src/test/resources/schema-test.sql` + 已有 dev 库用 H2 RunScript 单独 ALTER

### 15.5 摄像头与 HTTPS（硬约束，别绕）

浏览器的 `getUserMedia` **只在安全上下文可用**（HTTPS 或 localhost）。站点是纯 HTTP 时
点采集会被浏览器直接拒绝，**与代码无关**。另外大陆阿里云 ECS 上**未备案域名走 80/443
会被拦**，所以先落在 **8443**：

```bash
sudo bash deploy/server/setup-https.sh --self-signed     # 自签，立刻可用（浏览器会提示一次）
sudo bash deploy/server/setup-https.sh --domain exam.xx.edu.cn   # LE 的 DNS-01 签发（不碰 80 端口）
```

对应安全组要放行 `8443/tcp`。症状对照：`8443 => timeout` = 安全组没放行；
能连上但采集报 `PERMISSION_DENIED` = 证书警告没点继续 / 浏览器没给摄像头权限。

### 15.6 眨眼活体：为什么用自适应阈值

人脸库本地化在 `static/vendor/face-api/`（`@vladmandic/face-api` 1.7.15，MIT，
库 + 两组模型共 1.86MB，**登录页与学生列表按需加载**，不进首屏）。

眨眼判定用 68 关键点算 EAR。**阈值不是写死的 0.28/0.20**，而是热身期量出本人静息 EAR
后推导：`睁眼 = min(0.28, 0.85 × 基线)`、`闭眼 = min(0.20, 0.65 × 基线, 睁眼 - 0.02)`，
两者都取 `min`（自适应只放宽到本人够得着，不放宽标准）。
理由有实测背书：`.deploy-tools/simulate-blink.js` 模拟显示，
**静息 EAR 0.22 / 0.18 的人用固定阈值永远不满足 `ear >= 0.28` → 永不 armed →
明明眨了也超时成 `NO_BLINK`**；自适应后判定成功，而"浅眯"和"没眨眼"仍判不通过。

真机上万一还是过不去：开 `/face-test.html`，它的进度行会打出
`ear / 最低ear / 基线 / 阈值(arm/close) / 转头幅度 / 帧数` —— 这几个数就能定位：

| 观察到的现象 | 结论与下一步 |
| --- | --- |
| `最低ear` 贴着重叠阈值（差一点点） | 阈值偏紧 → 放宽 `close` 系数（现为 0.72×基线，上限 0.24） |
| `最低ear` ≈ 基线，且**帧数很大** | **这条链路测不出眨眼**（见下）→ 走转头通路 |
| `帧数` 很小（几十帧以内） | 采样率不够 → 降 `inputSize`（现 160）/ `detectIntervalMs`（现 40） |

**真机实测的结论（2026-09-17，手机 + 夸克浏览器）**：拿到一组非常关键的数据
`stage=detect ear=— hasFace=false blinks=0 基线=0.314 阈值=0.267/0.226 最低ear=0.267 帧数=207`
—— 207 帧采样里 **EAR 从未跌破阈值**（最低值 0.267 > 闭眼阈值 0.226），
说明在低分辨率 + 软件渲染的手机上，**68 点模型对「闭眼」几乎不响应**
（眼皮没被跟踪到，闭眼时点位基本不动）。此时**眨眼这条通路本身不可靠，
再怎么调阈值都是白调**。

因此活体改成**两条通路并行，任一完成即通过**：
- 眨眼：`ear` 先 ≥ `arm` 再 ≤ `close` 再回升（桌面摄像头通常很灵）
- **转头**：热身后取检测框中心 x 的中位数作中性位置，每帧算
  `|centerX - 基线x| / 脸宽`，连续两帧 ≥ `turnRatio`（默认 0.12）即通过。
  头部位移是几十像素级，4 fps 也测得准；单帧检测框抖动到不了 12% 脸宽
  （`simulate-turn.js` 用六类序列验证：微抖/单帧抖动不通过，左右转头通过）。

提示文案相应改成「请眨一下眼，或慢慢左右转头」——**给用户的指令必须是这条链路测得到的动作**。

**2026-09-17 用户验收后的两处调整**（都在真机上用过之后提的）：
1. **提示只留「转头」**：眨眼这条通路在手机端既然测不到，继续提示它只会误导用户。
   模块内仍保留眨眼判定（桌面端能用），但**提示文案只说转头**。
2. **不要一转头就成功 + 要有进度条**：改成**两段式**——
   第一段「转头到位」（连续 2 帧 ≥ 阈值，占进度 60%）→ 第二段「转回正前方」
   （回到中性位置 25% 以内，占进度 40%）→ 完成。这样一次偏移不算数，必须整个往返。
   进度通过 `onProgress` 的 `percent` / `phase` 上报，三个页面（注册采集、人脸录入、
   开考核验弹窗）各有一根 `.face-progress` 进度条，转到位变绿。
